# SONATLAS

MP3·WAV에서 보컬을 분리하고, 음높이·음 길이·BPM을 분석해 통합형 피아노 롤에서 자동 채보 결과를 검토·편집하는
Windows용 데스크톱 프로그램입니다. Python과 PySide6로 만들고 있습니다. 저장소 이름은 `Amp`, 파이썬 패키지 이름은 `amp`입니다.

**현재 버전: 0.3.0** — STEP 1(편집기), STEP 2(보컬 분리·자동 채보), 음원별 프로젝트 폴더 관리, STEP 2.5(안정화·검증 도구·음표 검출 v2)에
STEP 3(가사 인식·입력·음절 정렬·음표 연결)과 STEP 3.5(Windows GPU 점검 도구, F6 연속 실행 안정화, 끌어올림 음표·접근음 연결)를
더한 상태입니다. STEP 3.5 결과는 [STEP_3_5_VALIDATION_REPORT.md](STEP_3_5_VALIDATION_REPORT.md),
STEP 3 구현·검증 결과는 [STEP_3_IMPLEMENTATION_REPORT.md](STEP_3_IMPLEMENTATION_REPORT.md), 그 뒤 사용자 보고 4건의 수정은 [STEP_3_FOLLOWUP_REPORT.md](STEP_3_FOLLOWUP_REPORT.md),
STEP 2.5 검증 결과는 [STEP_2_5_VALIDATION_REPORT.md](STEP_2_5_VALIDATION_REPORT.md)에 있습니다.
실제 곡 4개(분리·같은 음 반복·잔향·Windows/GPU·악보 대비 오차) 평가는 [REAL_SONG_EVALUATION_REPORT.md](REAL_SONG_EVALUATION_REPORT.md)에 정리했습니다.

## 구현 현황

| 기능 | 상태 | 비고 |
|---|---|---|
| MP3/WAV 불러오기·재생 | 구현 | MP3·WAV·FLAC·OGG. 트랙별 솔로·음소거·음량 |
| 보컬·반주 분리 | 구현 | Demucs htdemucs, 별도 작업 프로세스, GPU 자동 사용. 별도 설치 필요 |
| 음높이 추출 | 구현 | librosa pYIN + 옥타브 오류·튐 보정. 무성 구간은 곡선을 끊음 |
| 자동 음표 검출 | 구현 | 비브라토·포르타멘토·장식음·재발음 처리, 민감도 3단계, 음 시작 끌어올림 합치기 (검출 v3) |
| 분석 실행 기록·비교 | 구현 | 실행마다 `analysis/runs/`에 기록, 최근 두 실행 비교 보고서 |
| 보컬 없는 구간 지정 | 구현 | 전주·간주에 섞인 반주로 음표가 생기는 것을 막음. 프로젝트별 저장 |
| 실제 음원 검증 도구 | 구현 | `scripts/validate_audio.py`. 실제 4곡 수치 검증 완료, 청취·정답 대비 정확도는 미확인 |
| BPM 추정 | 구현 | 추정값과 2배·절반 후보, 수동 수정, 첫 박 위치 조정. 4/4 가정 |
| 피아노 롤 (음표 + 피치 곡선) | 구현 | 레이어별 표시/숨김, 원본·수정·추가 음표 구분 |
| 음표 이동·분리·병합·길이 변경 | 구현 | 모두 실행 취소 가능 |
| 재분석 시 사용자 편집 보호 | 구현 | 비교 대화상자: 수정 유지하며 적용 / 전부 교체 / 취소 |
| 프로젝트 폴더 관리 | 구현 | 원본 복사·연결, stems·analysis·cache·exports 분리, 자동 복구 |
| 오디오 내보내기 (WAV/MP3) | 구현 | 개별·일괄, 비트레이트·WAV 형식 선택, 덮어쓰기 확인 |
| 이전 형식(.ampproj) 열기 | 구현 | 새 폴더로 변환, 원래 파일은 그대로 두고 백업 사본 생성 |
| MIDI 내보내기 | 미구현 | 메뉴에 '예정'으로 비활성 표시 |
| 가사 자동 인식 | 구현 | OpenAI Whisper(자동: GPU 여유가 넉넉하면 large-v3, 아니면 turbo), 빔 탐색 + 빈 구간 다시 듣기, 한국어 우선·영어·일본어, 언어 자동 감지, 환각 의심 구간 '검토 필요' 표시. 별도 설치 |
| 가사 직접 입력·붙여넣기·TXT 가져오기 | 구현 | 바뀐 줄만 다시 나눠 기존 시간·연결 유지, 줄 반복(후렴), 검토 완료 표시 |
| 음절 분리 | 구현 | 한글 음절 단위, 영어 규칙 기반, 일본어 가나 박 단위. 한자·숫자는 검토 표시 |
| 음절 시간 정렬 | 구현 | MMS 강제 정렬(직접 구현한 wav2vec2 + CTC). 모델 검출·추정·사용자 지정 시각을 구분. 처음 정렬 때 1.2GB 내려받음 |
| 음절·음표 연결 | 구현 | 1:1, 1:N(멜리스마), N:1(합쳐진 반복 발성), 접근음(가사는 주 음표에). 자동 연결 신뢰도·사용자 확정 별도 보관 |
| GPU·재생 점검 도구 | 구현 | `gpu_check.bat`(Whisper·MMS GPU 실행·메모리·취소), `playback_check.bat`(재생 경고 반복 점검). 사용자 PC에서 실행해 결과 파일을 보내는 용도 |
| 가사 레인·피아노 롤 가사 | 구현 | 음표 아래 가사, 재생 중 음절 강조, 음절 끌기·경계 조절·나누기·합치기, 구간 반복 재생 |
| 발음 기호, 자음·모음 시간, 멜리스마 분석 | 미구현 | STEP 4 |

**정확도에 관한 주의:** 자동 테스트는 합성 신호(포먼트 합성 목소리 + 합성 반주, 클릭 트랙)로만 했습니다.
실제 MP3 4곡은 분리부터 음표 검출·저장·재검출까지 오류 없이 처리되는 것과 처리 시간·메모리를 확인했습니다. 다만 정답 악보와 청취 확인이 없어
실제 곡의 분리 품질과 채보 정확도는 아직 모릅니다. 테스트 통과가 실제 곡의 정확도를 보장하지 않습니다.

## 프로젝트 폴더

오디오를 열면 음원마다 작업 폴더를 만듭니다. 기본 위치는 `문서\SONATLAS Projects`이고
**프로젝트 > 기본 프로젝트 위치 변경**에서 바꿀 수 있습니다.

```text
SONATLAS Projects/
└── 노래 이름/
    ├── original.mp3        원본 사본 (복사 방식일 때만. 연결 방식이면 경로만 기록)
    ├── stems/
    │   ├── vocals.wav      보컬 (원본과 같은 샘플레이트·길이, 24bit)
    │   ├── instrumental.wav
    │   └── stems.json      분리 모델·설정·검증 정보. 이 파일이 있어야 완성된 결과로 본다
    ├── analysis/
    │   ├── pitch.json      프레임별 시간·Hz·MIDI·신뢰도·유성 여부
    │   ├── notes.json      자동 분석 원본(analysis)과 사용자 편집(edits)을 나눠 저장
    │   ├── tempo.json      추정 BPM·후보·박 위치(analysis)와 사용자 템포(user)
    │   ├── lyrics.json     가사 텍스트(줄·단어·음절, 고유 id)·언어·자동 인식 원본·편집 이력
    │   ├── alignment.json  음절별 시작·끝·신뢰도·시각 출처·사용자 수정 여부, 음절↔음표 연결
    │   ├── runs/           분석 실행 기록 (성공한 실행만, 실행 ID별 JSON)
    │   └── reports/        실행 비교 보고서 (Markdown)
    ├── cache/              다시 만들 수 있는 중간 결과 (지워도 안전)
    ├── exports/            내보낸 파일
    ├── backup/             이전 형식 변환 전 백업 (있을 때만)
    └── project.json        프로젝트 ID·이름·원본 해시·상태·재생 위치·작업 공간
```

- 원본 파일은 읽기만 합니다. 수정하거나 지우지 않습니다.
- 같은 이름의 폴더가 있으면 `노래 이름 (2)`처럼 새 폴더를 만듭니다. 같은 음원으로 만든 프로젝트가 있으면 열지 새로 만들지 묻습니다.
- 프로젝트 안 파일은 상대 경로로 기록해서 폴더를 옮기거나 복사해도 열립니다. 연결한 원본을 찾지 못하면 **원본 다시 연결**을 안내합니다.
- 저장은 임시 파일에 쓴 뒤 바꿔치기합니다. `project.json`·`notes.json`·`tempo.json`·`lyrics.json`·`alignment.json`은 직전 파일을 `.bak`으로 남기고, 손상되면 `.bak`에서 불러옵니다.
- 가사 글자는 `lyrics.json`에만, 음절↔음표 연결은 `alignment.json`에만 둡니다. 음표(`notes.json` v2)는 가사를 모릅니다.
  0.2.x 프로젝트를 열면 `notes.json` 원본을 `backup/`에 남기고 새 형식으로 옮깁니다.
- 같은 프로젝트를 두 창·두 프로그램에서 동시에 열지 못하게 운영체제 파일 잠금(`.sonatlas.lock`)을 겁니다.
  프로그램이 비정상 종료되면 운영체제가 잠금을 풀어 다음에 바로 열 수 있습니다. 잠금 파일이 복사돼 와도 막히지 않습니다.
- 열려 있는 프로젝트 폴더를 복사해 열면 새 프로젝트 ID를 가진 독립 프로젝트로 엽니다. 폴더를 옮긴 경우는 같은 프로젝트로 봅니다.
- 연 뒤에 다른 곳(잠금이 통하지 않는 공유 폴더 등)에서 프로젝트 파일이 바뀌었으면 저장 전에 덮어쓸지 묻습니다.

## 설치 (Windows)

[python.org](https://www.python.org/downloads/windows/)에서 Windows용 Python 3.10 이상 64비트를 설치합니다(개발은 3.13, 사용자 Windows PC에서 3.14 + RTX 3070 Ti로 확인).
MSYS2·Cygwin에 들어 있는 Python은 쓸 수 없습니다. 설치된 공식 Python 목록은 아래 명령으로 볼 수 있습니다.

```bash
py -0p
```

### 1. 프로그램 실행

저장소 폴더의 `run.bat`을 실행합니다. 처음에는 가상 환경(`.venv`)을 만들고 필요한 패키지(PySide6, numpy, soundfile, scipy, librosa)를
설치한 뒤 켭니다. 두 번째부터는 바로 켜집니다. 이전 버전에서 만든 `.venv`가 있으면 빠진 패키지(librosa 등)를 알아서 보충합니다.

```bash
run.bat
```

### 2. 보컬 분리 설치 (한 번)

보컬 분리에는 PyTorch와 Demucs가 필요합니다. `run.bat`을 한 번 실행한 뒤 아래를 실행합니다.

```bash
install_separation.bat
```

NVIDIA GPU가 있으면 `nvidia-smi`가 알려 주는 드라이버 버전에 맞춰 CUDA판 PyTorch(약 2.5GB)를, 없으면 CPU판(약 200MB)을 설치합니다.
설치 후 프로그램 오른쪽 **분석 설정 > GPU 확인**을 누르면 GPU를 인식했는지 보여 줍니다.
처음 분석할 때 htdemucs 모델(약 80MB)을 인터넷에서 내려받습니다.

GPU가 있어도 CPU판을 원하면 `install_separation.bat --cpu`, 실행할 명령만 보려면 `--dry-run`을 붙입니다.
분리를 설치하지 않아도 분석 설정에서 보컬 분리를 **분리 안 함**으로 바꾸면 반주 없는 음원은 분석할 수 있습니다.

### 3. 가사 인식 설치 (한 번, 선택)

가사 자동 인식에는 OpenAI Whisper가 필요합니다. `install_separation.bat`으로 PyTorch를 먼저 설치한 뒤 아래를 실행합니다.

```bash
install_lyrics.bat
```

처음 인식할 때 Whisper turbo 모델(약 1.5GB), 처음 정렬할 때 MMS 정렬 모델(약 1.2GB)을 내려받습니다.
가사를 직접 입력하고 음표 순서대로 잇는 기능은 설치 없이 쓸 수 있습니다. 모델 파일 위치는 **가사 > 모델 파일 폴더 열기**로 엽니다.

## 사용법

1. **프로젝트 > 새 프로젝트 (오디오 열기)** (Ctrl+O): 파일을 고르면 프로젝트 이름·위치·원본 처리 방식(복사 / 연결)을 묻습니다.
2. **보컬 분석 실행** (F5): 보컬 분리 → 피치 추출 → BPM 추정 → 음표 검출 순서로 진행합니다. 진행률과 취소 버튼이 아래 상태 표시줄에 나옵니다.
3. 왼쪽 트랙 패널에서 Original / Vocals / Instrumental을 골라 듣고(헤드폰 = 그 트랙만), 파형을 바꿔 봅니다.
4. 피아노 롤에서 음표를 고칩니다. 오른쪽 **선택 음표**에 음계·MIDI·주파수·실제 피치·시간·박 위치·신뢰도가 나옵니다.
5. 설정을 바꾸고 **음표만 다시 검출** (Shift+F5): 분리·피치 결과를 재사용하고 음표 검출만 다시 합니다.
   0.2.0에서 분석한 프로젝트는 온셋·음량 정보가 예전 방식이라, 개선된 판정을 모두 쓰려면 **보컬 분석 실행**을 다시 하세요(안내가 나옵니다).
   **분석 > 최근 두 실행 비교 보고서**는 마지막 두 실행의 음표 차이를 `analysis/reports/`에 씁니다.
   전주·간주처럼 보컬이 없는데 분리 결과에 반주가 섞여 음표가 생기면, 그 음표들을 고르고 오른쪽 클릭 →
   **선택 구간을 보컬 없음으로 지정**을 누르세요. 그 구간은 피아노 롤에 빗금으로 표시되고, 음표를 다시 검출해 자동 음표만 지웁니다
   (직접 고친 음표는 남김). 구간 목록은 **분석 > 보컬 없는 구간…** 또는 분석 설정의 [편집…]에서 시간으로 고칠 수 있습니다.
6. **가사** (오른쪽 **가사** 탭, 피아노 롤 아래 가사 레인):
   - **가사 인식** (F6): 분리한 보컬로 Whisper를 돌립니다. 인식 원본은 따로 보관하고, 편집용 가사를 만듭니다.
     '인식한 뒤 바로 시간 정렬'(기본 켜짐)이면 이어서 정렬과 음표 연결까지 합니다. 진행 표시줄에 [1/3]·[2/3] 단계가,
     가사 탭에 단계별 장치(GPU 이름·최대 VRAM)와 시간이 나옵니다. 중간에 실패하거나 취소하면 그 전 결과는 남고,
     어디서부터 다시 하면 되는지(F6 / F7 / 음표 자동 연결) 알려 줍니다. 작업 전에 저장하지 않은 편집이 없었으면 끝난 뒤 저장합니다.
     끄면 음절 시간은 단어 시각을 나눈 추정값이라 실제 곡에서 음절 시작이 중앙값 0.24초 어긋났습니다. 이때는 F7로 정렬하세요.
     보컬이 거의 없는 구간·자막에서 흔한 문구·반복 같은 환각 의심 줄은 주황 배경과 이유로 표시합니다(지우지 않음).
   - 가사를 알고 있으면 편집기에 직접 쓰거나 붙여넣고 [적용], 또는 **가사 > 가사 TXT 가져오기**. 줄바꿈은 구간 구분 참고로만 씁니다.
   - **시간 정렬** (F7): 음절마다 시작·끝을 붙이고, 켜 두면 음표와 자동으로 잇습니다. 가사를 고친 뒤에는 **바뀐 부분만**(Shift+F7).
     직접 고친 음절 시간은 다시 정렬해도 바뀌지 않습니다.
   - 가사 레인에서 음절을 끌어 시간을 고치고, 오른쪽 클릭으로 음표 연결을 바꾸거나(피아노 롤에서 음표를 함께 고름) 구간을 반복 재생합니다.
   - 음절이 짧고 낮은 음표에서 시작해 위 음으로 올라가면 그 짧은 음표는 '접근음'(피아노 롤에 '·')으로 잇고 가사는 주 음표 아래에 씁니다.
     맞지 않으면 가사 레인 오른쪽 클릭 → **접근음 표시 해제**.
   - 시각 출처를 구분합니다: 모델 검출(실선) / 추정(점선, 인식 단어 시각을 글자 수로 나눈 값 등) / 직접 지정(굵은 선).
     CTC 정렬 모델은 음절 끝을 직접 주지 않아, 끝은 다음 음절 시작이나 보컬이 끊긴 곳으로 정한 추정값입니다.
7. **프로젝트 저장** (Ctrl+S), **내보내기 > 오디오 내보내기** (Ctrl+Shift+E).

음표는 모두 바이올렛, 실제 피치 곡선은 민트입니다. 음표 상태는 모양으로도 구분합니다.
꽉 찬 채움 = 분석 원본 그대로, 점선 테두리와 삼각 표식 = 수정함, 옅은 채움과 '+' = 직접 추가, 점 테두리 = 장식음.

**분석 설정 (오른쪽 패널)**

| 항목 | 기본값 | 설명 |
|---|---|---|
| 음표 분리 민감도 | 표준 | 단순(150ms, 재발음·장식음 무시) / 표준(100ms) / 정밀(70ms, 0.8반음, 얕은 재발음도 나눔) |
| 최소 음표 길이 | 100ms | 이보다 짧으면 이웃 음에 합침. 신뢰도가 높거나 따로 발음한 짧은 음은 장식음으로 남김 |
| 음높이 변화 기준 | 1반음 | 이만큼 바뀌어 일정 시간 유지되면 새 음표 |
| 분석 음역 | C2~C6 | 범위 밖 피치는 음표로 만들지 않음 |
| 보컬 없는 구간 | 없음 | 이 구간에서는 음표를 만들지 않음. 곡마다 다르므로 프로젝트에만 저장 |
| 보컬 분리 | htdemucs | '분리 안 함' = 원본을 그대로 분석 (반주 없는 음원용) |
| 처리 장치 | 자동 | GPU(CUDA)가 있으면 GPU, GPU 메모리가 부족하면 CPU로 다시 실행 |
| 캐시 재사용 | 켬 | 끄면 피치·BPM을 다시 계산. 분리는 **분리 다시 실행**으로 따로 요청 |
| 끌어올림 합치기 | 켬 | 목표 음보다 낮은 데서 미끄러져 올라가며 시작한 짧은 구간을 목표 음에 합침. 재발음이 있거나 0.12초 넘게 머문 음은 그대로. 정렬한 가사가 있으면 다음 음절의 음과는 합치지 않음. 끄면 STEP 3과 같은 결과 |

BPM은 자동 추정값이라 툴바에 "추정"으로 표시하고 정확하다고 판정하지 않습니다.
×2·½ 버튼으로 두 배·절반 후보를 고르고, 첫 박 위치로 박자선을 맞춥니다.

## 확인한 범위와 한계

- 개발 환경: Linux 컨테이너, Python 3.13, PySide6 6.12, librosa 1.0.1, torch 2.15.0(CPU), demucs 4.1.0.
  **Windows 실행, NVIDIA GPU 경로, Windows 실제 사운드카드 재생은 이 환경에서 확인하지 못했습니다.**
- 시험 결과는 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) 끝에 정리했습니다.
- 합성 노래(포먼트 목소리 + 반주, 13초)에서 htdemucs 분리부터 음표 10개 검출까지 정답과 일치했고, CPU 4코어에서 약 12초 걸렸습니다.
- 실제 MP3 4곡(4분 36초~5분 47초)은 CPU 4코어에서 분리에 곡 길이의 약 0.4배, 피치 추출에 17~22초가 걸렸고,
  분리 작업 프로세스는 최대 약 2.1~2.3GB RAM을 썼습니다. 분석 중 UI 이벤트 루프 지연은 13ms 이하였습니다.
- htdemucs는 떨림(비브라토) 없는 합성 정지음을 반주로 분류했습니다. 사람 목소리와 다른 소리는 분리가 잘 안 될 수 있습니다.
- pYIN은 한 사람의 멜로디를 전제로 합니다. 화음·코러스가 겹치면 피치가 흔들립니다.
- 재생은 장치가 원본 샘플레이트를 지원하지 않으면 선형 보간으로 변환합니다.
- 분리 결과 WAV는 24bit라서 ±1을 넘는 값은 잘립니다(드묾).
- 가사(STEP 3): 한국어 실제 곡 2개에서 Whisper turbo 글자 오류율 0.11~0.18(빔 탐색·다시 듣기 적용), MMS 정렬 음절 시작이 악보와 ±200ms 안에 96~97%.
  음절 끝은 추정값이고, 영어·일본어 실제 곡과 Windows·GPU 실행은 확인하지 못했습니다. 자세한 내용은 STEP_3_IMPLEMENTATION_REPORT.md.

## 문제 해결

**NVIDIA GPU가 있는데 분리가 느리다 / "GPU를 쓸 수 없어 CPU로 분리했습니다" 경고** — 설치된 PyTorch가 CPU판입니다.
`install_separation.bat`을 다시 실행하세요. CPU판을 지우고 드라이버에 맞는 GPU판을 설치한 뒤, GPU를 인식하는지 마지막에 알려 줍니다.
"드라이버가 오래되어"라는 안내가 나오면 NVIDIA 드라이버를 먼저 업데이트하세요. 설치 뒤 분석 설정의 [GPU 확인]이 GPU 이름을 보여 주면 됩니다.
"nvidia-smi는 있지만 CUDA 버전을 읽지 못했습니다"가 나오면 그 아래 줄에 nvidia-smi가 보여 준 내용이 있습니다. 드라이버와 통신하지 못한다는
문구면 드라이버를 다시 설치하세요. 명령 프롬프트에서 `nvidia-smi`를 실행해 오른쪽 위 `CUDA Version`이 보이면 그 버전에 맞춰 직접 고를 수 있습니다.

```bash
install_separation.bat --build cu126
```

(`cu126`은 CUDA 12.6 이상, `cu130`은 13.0 이상, `cu132`는 13.2 이상인 드라이버에서 씁니다.)

**`보컬 분리에는 PyTorch와 Demucs가 필요합니다`** — `install_separation.bat`을 실행하세요.
반주 없는 음원이라면 분석 설정의 보컬 분리를 '분리 안 함'으로 바꿔도 됩니다.

**`Demucs 모델(htdemucs)을 불러오지 못했습니다`** — 처음 분석할 때 모델을 내려받습니다. 인터넷 연결을 확인하세요.
모델은 사용자 폴더의 `.cache` 아래(Hugging Face 또는 torch hub 캐시)에 저장됩니다.

**`ModuleNotFoundError: No module named 'PySide6'`, `No module named pip` (C:\msys64\...)** — 공식 Python이 아니거나
가상 환경을 켜지 않은 상태입니다. `run.bat`을 쓰면 공식 Python을 찾아 처리합니다. `python -m amp`도 원인과 해결 방법을 안내합니다.

**`python`을 입력하면 Microsoft Store가 열린다** — 설치 때 PATH 추가를 하지 않은 경우입니다. `py`를 쓰세요.

로그는 `%LOCALAPPDATA%\SONATLAS\SONATLAS\logs\`에, 자동 저장본은 같은 위치의 `recovery\`에 있습니다.
프로그램 안에서는 상태 표시줄의 **로그** 버튼으로 펼쳐 볼 수 있습니다.
