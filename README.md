# SONATLAS

MP3·WAV에서 보컬을 분리하고, 음높이·음 길이·BPM을 분석해 통합형 피아노 롤에서 자동 채보 결과를 검토·편집하는
Windows용 데스크톱 프로그램입니다. Python과 PySide6로 만들고 있습니다. 저장소 이름은 `Amp`, 파이썬 패키지 이름은 `amp`입니다.

**현재 버전: 0.7.0 "Vocal Precision"** — 범용 자동 채보가 아니라 보컬·음원 정밀 분석 쪽으로 방향을 바꿨습니다
(피치 모델 선택·비교, 다중 피치·성부(실험), 비브라토·호흡·발성·발성 경계, 발음 사전, 베이스 박자 처리, 분석 선택·모델 관리·분석 레인,
분석 결과 내보내기, 검증 자료). v0.7.0 결과와 미검증 항목은 [SONATLAS_V0_7_0_IMPLEMENTATION_REPORT.md](SONATLAS_V0_7_0_IMPLEMENTATION_REPORT.md)에 있습니다.
그 아래에 STEP 1~5(편집기, 보컬 분리·자동 채보, 가사·음절 정렬, 발음·멜리스마, 청취·검토·내보내기·모델 비교)와
v0.6 보컬 다듬기(Hybrid 보컬, 음표 검출 v4, 교정 제안, 음절 정렬 다듬기, 품질 탭)가 그대로 있습니다.
v0.6.1~0.6.7(피치 다시 찾기 구간, 크롬북, 베이스 TAB, 악기 소리·악기 트랙) 결과는 [SONATLAS_V0_6_7_REPORT.md](SONATLAS_V0_6_7_REPORT.md),
v0.6 결과는 [SONATLAS_V0_6_0_IMPLEMENTATION_REPORT.md](SONATLAS_V0_6_0_IMPLEMENTATION_REPORT.md), STEP 3.5 결과는 [STEP_3_5_VALIDATION_REPORT.md](STEP_3_5_VALIDATION_REPORT.md),
STEP 3 구현·검증 결과는 [STEP_3_IMPLEMENTATION_REPORT.md](STEP_3_IMPLEMENTATION_REPORT.md), 그 뒤 사용자 보고 4건의 수정은 [STEP_3_FOLLOWUP_REPORT.md](STEP_3_FOLLOWUP_REPORT.md),
STEP 2.5 검증 결과는 [STEP_2_5_VALIDATION_REPORT.md](STEP_2_5_VALIDATION_REPORT.md)에 있습니다.

| 분석 선택·모델 관리·분석 레인·멈춤 기록 (v0.7.0) | 구현 | 의존 관계를 보여 주는 분석 선택 창(Ctrl+F5), 모델 관리 창, 비브라토·호흡·경계 레인(처음엔 꺼짐), 100ms 이상 화면 멈춤 기록 |
| 분석 결과 내보내기·검증 자료 (v0.7.0) | 구현 | JSON·CSV·TXT·PNG·구간 WAV. 10~30초 검증 자료(자료 종류 구분, 프로젝트 안에만, 학습·전송에 쓰지 않음) |
| 자음·모음 시간 측정 | 미구현 | v0.7.0에서 검토: 노래에 맞는 음소 정렬기와 검증 자료가 없어 음절 단위 분석을 유지 |

**정확도에 관한 주의:** 자동 테스트는 합성 신호(포먼트 합성 목소리 + 합성 반주, 클릭 트랙)로만 했습니다.
실제 MP3 4곡은 분리부터 음표 검출·저장·재검출까지 오류 없이 처리되는 것과 처리 시간·메모리를 확인했습니다. 다만 정답 악보와 청취 확인이 없어
실제 곡의 분리 품질과 채보 정확도는 아직 모릅니다. 테스트 통과가 실제 곡의 정확도를 보장하지 않습니다.

## 프로젝트 폴더

오디오를 열면 음원마다 작업 폴더를 만듭니다. 기본 위치는 `문서\SONATLAS Projects`이고
**프로젝트 > 기본 프로젝트 위치 변경**에서 바꿀 수 있습니다.

```text
SONATLAS Projects/
└── 노래 이름/
    ├── original.mp3        원본 사본 (복사 방식일 때만. 연결 방식이면 경로만 기록)
    ├── stems/
    │   ├── models/         모델별 분리 결과 (STEP 5). 다른 모델로 분리해도 덮어쓰지 않는다
    │   │   ├── htdemucs-1a2b3c4d5e/      vocals.wav · instrumental.wav (원본과 같은 샘플레이트·길이, 24bit) · stems.json
    │   │   │                             · bass.wav (v0.6.3, 베이스 TAB을 만들 때. 반주에도 그대로 들어 있음)
    │   │   │                             · drums.wav · other.wav (v0.6.4, 악기 소리를 분리할 때만)
    │   │   ├── htdemucs_6s-…/            v0.6.4 악기 소리: vocals·instrumental + drums·bass·guitar·piano·other
    │   │   ├── mel_roformer-6f7e8d9c0b/  키 = 원본·모델·버전·체크포인트·설정 파일 해시
    │   │   └── external-0123456789/      외부에서 가져온 결과 (원래 파일 이름·해시·어긋남 보정값)
    │   └── stems.json      지금 분석에 쓰는 결과를 가리키는 목록. 이 파일이 있어야 완성된 결과로 본다
    ├── analysis/
    │   ├── pitch.json      프레임별 시간·Hz·MIDI·신뢰도·유성 여부
    │   ├── notes.json      자동 분석 원본(analysis)과 사용자 편집(edits)을 나눠 저장
    │   ├── tempo.json      추정 BPM·후보·박 위치(analysis)와 사용자 템포(user)
    │   ├── lyrics.json     가사 텍스트(줄·단어·음절, 고유 id)·언어·자동 인식 원본·편집 이력·음절별 발음(v2)
    │   ├── alignment.json  음절별 시작·끝·신뢰도·시각 출처·사용자 수정 여부, 음절↔음표 연결, 사용자 멜리스마 판정(v3)
    │   ├── review.json     STEP 5 검토 상태 (항목 키·상태·근거 지문)
    │   ├── reference_score.json  STEP 5 가져온 참조 악보와 정렬 결과
    │   ├── model_compare.json    STEP 5 모델 비교에서 A·B로 고른 결과 키
    │   ├── bass.json       v0.6.3 베이스 TAB: 옵션, 베이스 자동 분석(음표·피치)과 사용자 작업본(edits)
    │   ├── runs/           분석 실행 기록 (성공한 실행만, 실행 ID별 JSON)
    │   └── reports/        실행 비교 보고서 (Markdown)
    ├── cache/              다시 만들 수 있는 중간 결과 (지워도 안전)
    ├── scores/             STEP 5 가져온 악보 파일 사본
    ├── exports/            내보낸 파일
    ├── backup/             이전 형식 변환 백업 (있을 때만). STEP 5부터 분리 결과는 backup/ 대신 stems/models/에 남는다
    └── project.json        프로젝트 ID·이름·원본 해시·상태·재생 위치·작업 공간
```

- 원본 파일은 읽기만 합니다. 수정하거나 지우지 않습니다.
- 같은 이름의 폴더가 있으면 `노래 이름 (2)`처럼 새 폴더를 만듭니다. 같은 음원으로 만든 프로젝트가 있으면 열지 새로 만들지 묻습니다.
- 프로젝트 안 파일은 상대 경로로 기록해서 폴더를 옮기거나 복사해도 열립니다. 연결한 원본을 찾지 못하면 **원본 다시 연결**을 안내합니다.
- 저장은 임시 파일에 쓴 뒤 바꿔치기합니다. `project.json`·`notes.json`·`tempo.json`·`lyrics.json`·`alignment.json`은 직전 파일을 `.bak`으로 남기고, 손상되면 `.bak`에서 불러옵니다.
- 가사 글자는 `lyrics.json`에만, 음절↔음표 연결은 `alignment.json`에만 둡니다. 음표(`notes.json` v2)는 가사를 모릅니다.
- 발음은 텍스트와 함께 바뀌므로 `lyrics.json`에, 사용자 멜리스마 판정은 연결과 함께 `alignment.json`에 둡니다. 자동 멜리스마 판정과
  음절 길이는 음표·연결·피치에서 언제든 다시 계산되므로 저장하지 않습니다(두 곳에 두면 어긋날 수 있어서).
  0.2.x 프로젝트를 열면 `notes.json` 원본을 `backup/`에 남기고 새 형식으로 옮깁니다.
- 같은 프로젝트를 두 창·두 프로그램에서 동시에 열지 못하게 운영체제 파일 잠금(`.sonatlas.lock`)을 겁니다.
  프로그램이 비정상 종료되면 운영체제가 잠금을 풀어 다음에 바로 열 수 있습니다. 잠금 파일이 복사돼 와도 막히지 않습니다.
- 열려 있는 프로젝트 폴더를 복사해 열면 새 프로젝트 ID를 가진 독립 프로젝트로 엽니다. 폴더를 옮긴 경우는 같은 프로젝트로 봅니다.
- 연 뒤에 다른 곳(잠금이 통하지 않는 공유 폴더 등)에서 프로젝트 파일이 바뀌었으면 저장 전에 덮어쓸지 묻습니다.

## 설치 (Windows)

[python.org](https://www.python.org/downloads/windows/)에서 Windows용 Python 3.10 이상 64비트를 설치합니다(개발은 3.13, 사용자 Windows PC에서 3.14 + RTX 3070 Ti로 확인).
MSYS2·Cygwin에 들어 있는 Python은 쓸 수 없습니다. 설치된 공식 Python 목록은 아래 명령으로 볼 수 있습니다.

```bash
py -0p
```

### 1. 프로그램 실행

저장소 폴더의 `run.bat`을 실행합니다. 처음에는 가상 환경(`.venv`)을 만들고 필요한 패키지(PySide6, numpy, soundfile, scipy, librosa, mido, PyYAML)를
설치한 뒤 켭니다. 두 번째부터는 바로 켜집니다. 이전 버전에서 만든 `.venv`가 있으면 빠진 패키지(librosa, mido 등)를 알아서 보충합니다.

```bash
run.bat
```

### 2. 보컬 분리 설치 (한 번)

보컬 분리에는 PyTorch와 Demucs가 필요합니다. `run.bat`을 한 번 실행한 뒤 아래를 실행합니다.

```bash
install_separation.bat
```

NVIDIA GPU가 있으면 `nvidia-smi`가 알려 주는 드라이버 버전에 맞춰 CUDA판 PyTorch(약 2.5GB)를, 없으면 CPU판(약 200MB)을 설치합니다.
설치 후 프로그램 오른쪽 **분석 설정 > GPU 확인**을 누르면 GPU를 인식했는지 보여 줍니다.
처음 분석할 때 htdemucs 모델(약 80MB)을 인터넷에서 내려받습니다.

GPU가 있어도 CPU판을 원하면 `install_separation.bat --cpu`, 실행할 명령만 보려면 `--dry-run`을 붙입니다.
분리를 설치하지 않아도 분석 설정에서 보컬 분리를 **분리 안 함**으로 바꾸면 반주 없는 음원은 분석할 수 있습니다.

### 3. 가사 인식 설치 (한 번, 선택)

가사 자동 인식에는 OpenAI Whisper가 필요합니다. `install_separation.bat`으로 PyTorch를 먼저 설치한 뒤 아래를 실행합니다.

```bash
install_lyrics.bat
```

처음 인식할 때 Whisper turbo 모델(약 1.5GB), 처음 정렬할 때 MMS 정렬 모델(약 1.2GB)을 내려받습니다.
가사를 직접 입력하고 음표 순서대로 잇는 기능은 설치 없이 쓸 수 있습니다. 모델 파일 위치는 **가사 > 모델 파일 폴더 열기**로 엽니다.

## 설치 (크롬북·리눅스)

크롬북의 Linux 개발 환경(설정 > 고급 > 개발자 > Linux 개발 환경)에서 확인한 환경: x86_64, Debian 13(glibc 2.41).
데비안·우분투 x86_64도 같은 방법입니다. ARM 칩은 glibc 2.39 이상이어야 PySide6가 pip로 설치됩니다.

1. Linux 터미널에서 저장소를 받고 설치합니다 (처음 한 번, 시스템 패키지 설치에 sudo 사용).
   크롬북 Linux에는 git이 없으니 먼저 설치합니다. git 없이 하려면 릴리스의 `SONATLAS-…-chromebook-linux.tar.gz`를
   파일 앱에서 'Linux 파일'로 옮긴 뒤 `tar xzf`로 풀고 그 폴더에서 `./install_chromebook.sh`를 실행합니다.

```bash
sudo apt-get update && sudo apt-get install -y git
```

```bash
git clone -b claude/dazzling-mendel-mw3z4s https://github.com/ceg914/Amp.git && cd Amp
```

```bash
./install_chromebook.sh
```

2. 런처의 'Linux 앱'에서 **SONATLAS**를 누르거나 `./run.sh`로 실행합니다.

**가벼운 모드:** 기본 설치에는 PyTorch를 넣지 않고(가상 환경 약 1.2GB), 실행하면 가벼운 모드로 켜집니다.
피치·음표 검출, 편집, 가사 직접 입력과 음표 순서 연결, 재생·반복·느린 재생, 검토·교정 제안·품질, 내보내기,
피치 다시 찾기 구간은 그대로 씁니다. 모델 비교·Hybrid·RoFormer·GPU 확인·가사 자동 인식·자동 정렬은 숨깁니다.
보컬 분리는 다른 PC에서 분리한 파일을 **분석 > 외부 분리 결과 가져오기**로 넣거나, Windows에서 만든 프로젝트 폴더를 그대로 엽니다
(이미 분리한 결과가 있으면 다시 분리하지 않습니다). 반주 없는 보컬 파일은 분석 설정의 보컬 분리를 '분리 안 함'으로 둡니다.

크롬북에서 직접 분리하려면 `./install_chromebook.sh --separation` (CPU용 PyTorch + Demucs, 약 1.2GB 추가).
5분 곡 분리에 메모리를 2.0~2.3GB 쓰고, 4코어 Xeon에서 110~170초 걸렸습니다(크롬북에서는 재지 않았습니다).
설치해도 가벼운 모드를 끄려면 `./run.sh --full`.

## 사용법

1. **프로젝트 > 새 프로젝트 (오디오 열기)** (Ctrl+O): 파일을 고르면 프로젝트 이름·위치·원본 처리 방식(복사 / 연결)을 묻습니다.
2. **보컬 분석 실행** (F5): 보컬 분리 → 피치 추출 → BPM 추정 → 음표 검출 순서로 진행합니다. 진행률과 취소 버튼이 아래 상태 표시줄에 나옵니다.
3. 왼쪽 트랙 패널에서 Original / Vocals / Instrumental을 골라 듣고(헤드폰 = 그 트랙만), 파형을 바꿔 봅니다.
   오른쪽 탭은 **속성·분석**, **노래 분석**(가사·검토·교정 제안·품질·악보 비교, 모델 비교 중에는 모델 차이),
   **악기**(악기 소리·베이스 TAB) 세 묶음입니다(v0.6.4).
4. 피아노 롤에서 음표를 고칩니다. 오른쪽 **선택 음표**에 음계·MIDI·주파수·실제 피치·시간·박 위치·신뢰도가 나옵니다.
5. 설정을 바꾸고 **음표만 다시 검출** (Shift+F5): 분리·피치 결과를 재사용하고 음표 검출만 다시 합니다.
   0.2.0에서 분석한 프로젝트는 온셋·음량 정보가 예전 방식이라, 개선된 판정을 모두 쓰려면 **보컬 분석 실행**을 다시 하세요(안내가 나옵니다).
   **분석 > 최근 두 실행 비교 보고서**는 마지막 두 실행의 음표 차이를 `analysis/reports/`에 씁니다.
   전주·간주처럼 보컬이 없는데 분리 결과에 반주가 섞여 음표가 생기면, 그 음표들을 고르고 오른쪽 클릭 →
   **선택 구간을 보컬 없음으로 지정**을 누르세요. 그 구간은 피아노 롤에 빗금으로 표시되고, 음표를 다시 검출해 자동 음표만 지웁니다
   (직접 고친 음표는 남김). 구간 목록은 **분석 > 보컬 없는 구간…** 또는 분석 설정의 [편집…]에서 시간으로 고칠 수 있습니다.
   분석 설정의 **보컬 트랙에서도 비우기**(기본 켬)가 켜져 있으면 그 구간에서 보컬 트랙을 무음으로 만들고, 뺀 소리는 반주 트랙에 더합니다
   (재생·파형·오디오 내보내기에 적용, 경계 0.02초 페이드, 보컬 + 반주 = 원래 합). 분리 결과 파일 `stems/*.wav`와 분석 결과는 바꾸지 않습니다.
   **다른 분리 프로그램 결과 쓰기**: Demucs 보컬에 신스·패드 소리가 많이 섞이면, Ultimate Vocal Remover(UVR) 같은 프로그램에서
   보컬 전용 모델(예: Mel-Band RoFormer 계열)로 같은 원본 파일을 분리한 뒤 **분석 > 외부 분리 결과 가져오기…**에서 보컬 파일을 고르세요.
   반주 파일은 선택입니다(비우면 원본 − 보컬). 원본과 샘플레이트·시간 어긋남(±2초)·길이 차이(±3초)를 자동으로 맞추고,
   원본과 맞지 않는 파일(다른 곡, 음량을 크게 바꾼 파일)은 가져오지 않습니다. 기존 분리 결과는 `stems/models/`에 그대로 남습니다.
   가져오면 새 보컬로 다시 분석할지 묻고, 이후 **보컬 분석 실행**은 Demucs를 다시 돌리지 않고 가져온 보컬로 피치·음표를 계산합니다.
   **보컬 분리 다시 실행**을 누르면 그때만 분석 설정에서 고른 방식으로 다시 분리합니다(가져온 결과는 `stems/models/`에 남음).
   **RoFormer를 앱 안에서 쓰기**: 분석 설정의 **보컬 분리**에서 *Mel-Band RoFormer (모델 파일 지정)*를 고르고 [모델 파일…]에서
   직접 받은 체크포인트(.ckpt·.pth·.safetensors)를 지정합니다. 고르면 작업 프로세스가 파일을 읽어 구조를 확인하고 결과(파라미터 수·대역 수)를 패널에 표시합니다.
   층 수·대역 수·머리 수는 파일의 텐서 모양에서 읽고, STFT가 기본값(n_fft 2048, hop 441, 44.1kHz)과 다른 모델이면 함께 받은 `.yaml`도 지정하세요.
   파일은 `torch.load(weights_only=True)`로 텐서만 읽습니다. 8초 조각을 절반씩 겹쳐 돌리고(설정 파일에 값이 있으면 그 값), 반주는 원본 − 보컬입니다.
   같은 모델 파일(내용 해시)·설정 파일로 만든 결과가 있으면 다시 분리하지 않습니다. 모델 파일 경로는 컴퓨터마다 다르므로 프로젝트가 아니라 프로그램 설정에 저장합니다.
   이 컨테이너의 CPU(4스레드)에서 기본 크기 모델(파라미터 228.2M)은 8초 조각 하나에 11.5초, 메모리 최대 2.2GB였습니다
   (무작위 가중치로 잰 속도. 5분 곡이면 CPU로 15분 안팎). GPU 속도와 실제 가중치의 분리 품질은 확인하지 않았습니다.
   지원 범위: ZFTurbo/Music-Source-Separation-Training 형식의 Mel-Band RoFormer(선형 어텐션·PoPE 변형 제외). BS-RoFormer는 아직 지원하지 않습니다.
   SONATLAS는 UVR이나 RoFormer 가중치를 포함하거나 내려받지 않습니다. 모델마다 가중치 라이선스가 다르니 쓰는 쪽에서 확인하세요.
6. **가사** (오른쪽 **노래 분석 > 가사** 탭, 피아노 롤 아래 가사 레인):
   - **가사 인식** (F6): 분리한 보컬로 Whisper를 돌립니다. 인식 원본은 따로 보관하고, 편집용 가사를 만듭니다.
     '인식한 뒤 바로 시간 정렬'(기본 켜짐)이면 이어서 정렬과 음표 연결까지 합니다. 진행 표시줄에 [1/3]·[2/3] 단계가,
     가사 탭에 단계별 장치(GPU 이름·최대 VRAM)와 시간이 나옵니다. 중간에 실패하거나 취소하면 그 전 결과는 남고,
     어디서부터 다시 하면 되는지(F6 / F7 / 음표 자동 연결) 알려 줍니다. 작업 전에 저장하지 않은 편집이 없었으면 끝난 뒤 저장합니다.
     끄면 음절 시간은 단어 시각을 나눈 추정값이라 실제 곡에서 음절 시작이 중앙값 0.24초 어긋났습니다. 이때는 F7로 정렬하세요.
     보컬이 거의 없는 구간·반복 같은 환각 의심 줄은 주황 배경과 이유로 표시합니다(지우지 않음).
     '한글자막 by …', '시청해 주셔서 감사합니다', 줄 전체가 '감사합니다'뿐인 것처럼 영상 자막에서 흔한 문구는 가사에 넣지 않고
     인식 원본에만 '✕ … 가사에 넣지 않음'으로 남깁니다. 실제 가사라면 편집기에 직접 넣으세요.
   - 가사를 알고 있으면 편집기에 직접 쓰거나 붙여넣고 [적용], 또는 **가사 > 가사 TXT 가져오기**. 줄바꿈은 구간 구분 참고로만 씁니다.
   - **시간 정렬** (F7): 음절마다 시작·끝을 붙이고, 켜 두면 음표와 자동으로 잇습니다. 가사를 고친 뒤에는 **바뀐 부분만**(Shift+F7).
     직접 고친 음절 시간은 다시 정렬해도 바뀌지 않습니다.
   - 가사 레인에서 음절을 끌어 시간을 고치고, 오른쪽 클릭으로 음표 연결을 바꾸거나(피아노 롤에서 음표를 함께 고름) 구간을 반복 재생합니다.
   - 음절이 짧고 낮은 음표에서 시작해 위 음으로 올라가면 그 짧은 음표는 '접근음'(피아노 롤에 '·')으로 잇고 가사는 주 음표 아래에 씁니다.
     맞지 않으면 가사 레인 오른쪽 클릭 → **접근음 표시 해제**.
   - 시각 출처를 구분합니다: 모델 검출(실선) / 추정(점선, 인식 단어 시각을 글자 수로 나눈 값 등) / 직접 지정(굵은 선).
     CTC 정렬 모델은 음절 끝을 직접 주지 않아, 끝은 다음 음절 시작이나 보컬이 끊긴 곳으로 정한 추정값입니다.
7. **발음·길이·멜리스마** (STEP 4, 가사 탭 아래 **발음 · 가창 길이 · 멜리스마**):
   - 가사를 넣으면 발음이 자동으로 생깁니다. 음절을 고르면 발음·IPA·적용한 규칙(연음·비음화 등과 조항 번호)·불확실한 이유가 나옵니다.
     발음은 가사 텍스트에서 규칙으로 추정한 값이며, 가수가 실제로 어떻게 불렀는지 들은 결과가 아닙니다.
   - [발음 적용]으로 고치면 '사용자 확정'이 되어 다시 생성해도 바뀌지 않습니다. 원문이나 앞뒤 문맥이 바뀌면 '재검토 필요'만 붙습니다.
     [기본 발음으로]는 자동 발음으로 되돌립니다. 빈 값은 '앞 음절과 합쳐 발음'입니다.
   - 음절 구간 길이(정렬 시작~끝, 끝은 대부분 추정)와 유성 가창 길이(그 구간에서 피치가 잡힌 시간, 무성 자음 제외·분리 잔향 포함 가능)를 따로 보여 줍니다.
   - 멜리스마: 자동 판정과 음높이 순서(예: E4 → F#4 → G4)·범위·방향. 가사 레인 오른쪽 클릭이나 패널 단추로 **멜리스마로 확정**
     (피아노 롤에서 음표를 2개 이상 고르면 그 음표로) / **멜리스마 아님** / **선택 음표 추가·빼기** / **자동 판정으로**.
   - **보기 > 가사·발음 표시**: 가사만 / 발음만 / 가사 + 발음 / 가사 + IPA / 전체, 멜리스마 강조(괄호선), 음절 구간 길이(ms).
     확대가 작아 글상자가 겹치면 일부를 생략합니다(확대하면 보입니다).

     '청취용 음량 맞춤'은 큰 쪽을 작은 쪽에 맞춰 재생 음량만 줄입니다(분리 WAV는 그대로). 스펙트로그램은 A만·B만·좌우·위아래·차이로 보고,
     두 쪽 모두 같은 dB 범위를 씁니다. 피아노 롤에는 A(바이올렛 점선)·B(민트 점점선) 자동 음표와 피치 곡선이 겹쳐 그려집니다.
     '모델 차이' 탭과 검토 탭의 '모델 비교' 항목은 차이만 보여 줍니다. 정답 채보가 없으므로 어느 모델이 정확하다고 판정하지 않습니다.
     [A/B를 분석에 사용…]은 바뀔 항목(자동 음표·피치 곡선·연결·멜리스마·음절 시간)을 먼저 보여 주고, 사용자 편집은 '수정 유지'로 지킵니다.
     필요 없는 분리 결과는 목록에서 골라 [지우기…]로 정리합니다(지금 분석에 쓰는 결과는 지울 수 없음).
   - **내보내기 > 채보·가사 내보내기**: USTX(OpenUtau)·UFData·MIDI·MusicXML·JSON·CSV·LRC. 가수·phonemizer는 OpenUtau에서 고르세요.

   - **피아노 롤에서 베이스 편집** (Ctrl+Shift+B, 분석 메뉴의 **베이스 편집 모드**): 가운데 피아노 롤이 베이스로 바뀌고 상태 표시줄에
     '베이스 편집 중'이 나옵니다. 편집 방법·단축키는 보컬과 같고, Ctrl+Z는 보이는 쪽(베이스) 기록만 되돌립니다.
     다시 분석해도 고치거나 추가한 음표는 남깁니다(보컬 재분석의 '수정 유지'와 같은 규칙).
   - 탭 아래 미리보기는 지금 음표로 만든 TAB입니다. 줄·프렛은 손 위치 이동이 적은 경로로 고르고, 조율·최대 프렛 밖 음은 빼고 개수를 알려 줍니다.
   - **GP5 내보내기**(Guitar Pro·TuxGuitar·MuseScore), **텍스트 TAB 내보내기**(메모장용 UTF-8). GP5에는 처음 BPM 하나만 들어가고,
     마디를 넘는 음은 붙임줄로 잇습니다. 셋잇단·슬라이드·해머링·뮤트 음은 아직 만들지 않습니다.
   - **베이스 소리 내보내기 (WAV·MP3)**: 분리해 둔 베이스를 파일로 저장합니다(WAV 24bit는 분리 결과 그대로, MP3 320kbps).
     베이스 분석을 한 번 하면 생기고, 분리를 새로 하지는 않습니다. 파일은 `stems/models/htdemucs-…/bass.wav`에도 있습니다.
   - **베이스만 듣기**: 분리해 둔 베이스만 들립니다. 왼쪽 트랙 패널 Bass 줄의 헤드폰과 같은 단추입니다.
11. **악기 소리** (v0.6.4, 오른쪽 **악기 > 악기 소리** 탭): 악기 소리를 따로 뽑아 파일로 저장합니다. 악보는 만들지 않습니다.
   - **드럼·베이스·나머지 분리** (Demucs htdemucs) / **기타·피아노까지 분리** (Demucs htdemucs_6s, 처음에 약 55MB 내려받음).
     곡 전체를 한 번 더 분리하며, 이미 있는 악기 파일은 다시 만들지 않습니다. 보컬 분석에 쓰는 분리 결과와 보컬·반주 파일은 바꾸지 않습니다.
   - **분리할 소리** (v0.6.7): 기본은 **보컬 분석의 반주**입니다. 보컬 분석에서 이미 보컬을 뺀 반주를 분리하므로 악기 파일에 보컬이 덜 섞입니다
     (원곡을 바로 분리하면 악기마다 보컬이 들린다는 사용자 보고에서 출발). 결과는 보컬 분석에 쓰는 분리 결과 폴더에 악기 파일로 더하고
     줄에 '○○ 반주에서'라고 적습니다. 그 폴더에 이미 있는 악기(htdemucs로 보컬 분석했으면 드럼·베이스·나머지)는 다시 만들지 않습니다.
     보컬 분석을 하지 않았으면 **원본**에서 분리합니다(직접 고를 수도 있음).
   - 악기마다 **내보내기…**(WAV 24bit·MP3 320kbps), **위치**(파일이 있는 폴더 열기). 줄에 어느 모델로 뽑았는지와 길이가 나옵니다.
   - **악기 트랙** (v0.6.6): 뽑은 악기는 왼쪽 트랙 패널의 Original·Vocals·Instrumental 아래에 같은 모양의 줄(Drums·Bass·Guitar·Piano·Other)로
     나옵니다. 헤드폰 = 그 악기만(솔로, 여러 개면 함께), 스피커 = 음소거, 막대 = 음량, 줄을 누르면 그 악기 파형·스펙트로그램.
     악기 소리는 반주에 이미 들어 있어 **처음에는 음소거**입니다. 음소거를 풀면 지금 들리는 소리에 더해집니다
     (예: Original·Instrumental 음소거 + Vocals + Bass 음소거 해제 = 보컬과 베이스만).
     재생 중에 바꿔도 끊기지 않고, 위치·반복 구간·속도는 그대로입니다. 들리거나 파형을 보는 동안만 그 악기 파일을 메모리에 올리고
     (4분 곡 악기 하나에 약 85MB) 다시 음소거하면 내립니다. 음소거·솔로·음량은 프로젝트에 저장합니다.
   - **묶음 음소거** (v0.6.7): 트랙 창 위의 **전부 음소거**, '원본·분리 트랙' 묶음과 '악기' 묶음의 **음소거**. 켜면 그 묶음이 들리지 않고
     (솔로도 끔), 다시 누르면 누르기 전 상태로 돌아갑니다. 그사이 줄 하나를 직접 켜면 단추가 풀리고, 그 뒤에 누르면 소리를 켭니다
     (전부 음소거를 이렇게 풀 때는 원본·분리 트랙만 켜고 악기는 겹치지 않게 음소거로 둡니다).
   - '나머지'는 보컬과 앞 악기들을 뺀 소리라 htdemucs와 6s의 내용이 다릅니다. 같은 악기가 여러 결과에 있으면 지금 분석에 쓰는 결과 →
     htdemucs → 6s 순서로 고릅니다. Demucs 설명서에 6s의 피아노 분리는 아직 잘 되지 않는다고 적혀 있습니다.
   - 악기 하나가 1분에 약 16MB(WAV 24bit)를 씁니다. 크롬북 가벼운 모드처럼 분리를 설치하지 않았으면 분리 단추는 꺼지고, 이미 뽑은 파일은 내보낼 수 있습니다.

음표는 모두 바이올렛, 실제 피치 곡선은 민트입니다. 음표 상태는 모양으로도 구분합니다.
꽉 찬 채움 = 분석 원본 그대로, 점선 테두리와 삼각 표식 = 수정함, 옅은 채움과 '+' = 직접 추가, 점 테두리 = 장식음.

**분석 설정 (오른쪽 패널)**

| 항목 | 기본값 | 설명 |
|---|---|---|
| 음표 분리 민감도 | 표준 | 단순(150ms, 재발음·장식음 무시) / 표준(100ms) / 정밀(70ms, 0.8반음, 얕은 재발음도 나눔) |
| 최소 음표 길이 | 100ms | 이보다 짧으면 이웃 음에 합침. 신뢰도가 높거나 따로 발음한 짧은 음은 장식음으로 남김 |
| 음높이 변화 기준 | 1반음 | 이만큼 바뀌어 일정 시간 유지되면 새 음표 |
| 분석 음역 | C2~C6 | 범위 밖 피치는 음표로 만들지 않음 |
| 보컬 없는 구간 | 없음 | 이 구간에서는 음표를 만들지 않음. 곡마다 다르므로 프로젝트에만 저장 |
| 보컬 분리 | htdemucs | '분리 안 함' = 원본을 그대로 분석 (반주 없는 음원용) |
| 처리 장치 | 자동 | GPU(CUDA)가 있으면 GPU, GPU 메모리가 부족하면 CPU로 다시 실행 |
| 캐시 재사용 | 켬 | 끄면 피치·BPM을 다시 계산. 분리는 **분리 다시 실행**으로 따로 요청 |
| 끌어올림 합치기 | 켬 | 목표 음보다 낮은 데서 미끄러져 올라가며 시작한 짧은 구간을 목표 음에 합침. 재발음이 있거나 0.12초 넘게 머문 음은 그대로. 정렬한 가사가 있으면 다음 음절의 음과는 합치지 않음. 끄면 STEP 3과 같은 결과 |

BPM은 자동 추정값이라 툴바에 "추정"으로 표시하고 정확하다고 판정하지 않습니다.
×2·½ 버튼으로 두 배·절반 후보를 고르고, 첫 박 위치로 박자선을 맞춥니다.

## 확인한 범위와 한계

- 개발 환경: Linux 컨테이너, Python 3.13, PySide6 6.12, librosa 1.0.1, torch 2.15.0(CPU), demucs 4.1.0.
  **Windows 실행, NVIDIA GPU 경로, Windows 실제 사운드카드 재생은 이 환경에서 확인하지 못했습니다.**
- 시험 결과는 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) 끝에 정리했습니다.
- 합성 노래(포먼트 목소리 + 반주, 13초)에서 htdemucs 분리부터 음표 10개 검출까지 정답과 일치했고, CPU 4코어에서 약 12초 걸렸습니다.
- 실제 MP3 4곡(4분 36초~5분 47초)은 CPU 4코어에서 분리에 곡 길이의 약 0.4배, 피치 추출에 17~22초가 걸렸고,
  분리 작업 프로세스는 최대 약 2.1~2.3GB RAM을 썼습니다. 분석 중 UI 이벤트 루프 지연은 13ms 이하였습니다.
- htdemucs는 떨림(비브라토) 없는 합성 정지음을 반주로 분류했습니다. 사람 목소리와 다른 소리는 분리가 잘 안 될 수 있습니다.
- pYIN은 한 사람의 멜로디를 전제로 합니다. 화음·코러스가 겹치면 피치가 흔들립니다.
- 재생은 장치가 원본 샘플레이트를 지원하지 않으면 선형 보간으로 변환합니다.
- 분리 결과 WAV는 24bit라서 ±1을 넘는 값은 잘립니다(드묾).
- 가사(STEP 3): 한국어 실제 곡 2개에서 Whisper turbo 글자 오류율 0.11~0.18(빔 탐색·다시 듣기 적용), MMS 정렬 음절 시작이 악보와 ±200ms 안에 96~97%.
  음절 끝은 추정값이고, 영어·일본어 실제 곡과 Windows·GPU 실행은 확인하지 못했습니다. 자세한 내용은 STEP_3_IMPLEMENTATION_REPORT.md.
- STEP 3.5: 끌어올림 합치기·접근음 연결로 두 곡의 가사 글자 위치 정확도 0.853→0.904, 0.883→0.982(두 곡은 규칙을 정할 때도 본 곡이라 독립 검증 아님).
  사용자 Windows PC(RTX 3070 Ti 8GB)에서 Whisper large-v3·turbo와 MMS 정렬이 GPU로 돌고, 취소 뒤 GPU 메모리가 돌아오는 것을 확인했습니다
  (large-v3: 60초 소리 인식 18.7초, VRAM 최대 3.4GB). 같은 PC에서 `playback_check.bat` 3회(84단계) 동안 재생 장치 경고 0을 확인했습니다.
  Windows에서 출력 장치를 바꿀 때의 동작은 아직 확인하지 못했습니다. 재생기는 Windows에서 기본 출력 장치를 Qt 대신 Windows에 직접 물어 씁니다(Qt의 기본 장치 표시가 Windows를 따라가지 못했을 가능성이 점검 기록에 보여서). 자세한 내용은 STEP_3_5_VALIDATION_REPORT.md.
- 악기 듣기(v0.6.5): 재생 중에 트랙을 더하거나 빼면 예전에는 출력 장치를 다시 열어, 리눅스 가상 장치에서 약 1.5초 소리가 멈췄습니다.
  이제 보통 속도에서는 장치를 그대로 두고 믹서에서 트랙을 더하고 빼며, 새 트랙은 12ms 동안 음량을 올립니다(같은 장치에서 끊김 없음 확인).
  분리 결과를 불러오거나 모델 비교 A/B 트랙을 올릴 때도 같은 방식입니다. 느린 재생 중에는 예전처럼 다시 엽니다. Windows에서는 확인하지 못했습니다.
- 반주에서 악기 분리(v0.6.7): 조각 나비를 htdemucs로 보컬 분석한 반주에서 6s로 다시 분리하니, 악기 파일에서 보컬과 같은 모양의 성분이
  피아노 5~6dB, 베이스·나머지 2~3dB 줄고 드럼·기타는 거의 같았습니다(근사 지표, 기준 보컬 두 가지). 사용자의 RoFormer 반주로는 재지 못했습니다.
- 악기 소리(v0.6.4): 조각 나비(4분 36초)를 앱의 작업 프로세스로 htdemucs_6s 분리해 다섯 악기 파일이 원본과 같은 길이로 나오는 것을
  확인했습니다(CPU 4코어 111초, 최대 2.6GB). 원곡 전체 대비 음량은 드럼 −9.6dB, 기타 −10.9dB, 나머지 −19.0dB, 피아노 −23.7dB였고,
  사용자가 이 곡의 결과를 들어 보니 기타·피아노 파일에 다른 소리가 조금 섞여 있었습니다(음역이 겹치는 악기).
  다른 곡과 GPU 실행은 확인하지 못했습니다.
- 베이스 TAB(v0.6.3): 기준 TAB이 있는 실제 곡은 조각 나비 1곡(사용자가 준 GP5, 575음)뿐입니다. 이 곡의 htdemucs 베이스에서
  음 시작 ±100ms·음높이 일치 F1 0.915(±50ms 0.887), 옥타브 오류 0, 앱이 추정한 템포(94.0 BPM)로 16분음표 칸까지 맞은 음 90.6%,
  그중 줄·프렛이 기준 TAB과 같은 음 67.9%였습니다. 퉁김 분할 규칙(4dB)과 줄·프렛 가중치는 이 곡을 보며 골라 독립 검증이 아닙니다.
  베이스 분리 소리는 사용자가 이 곡을 직접 듣고 잘 분리됐다고 확인했습니다(다른 곡은 아직 듣지 않음).
  5현 B0와 빠른 16분음표는 합성 소리로만 확인했습니다. GP5 파일은 PyGuitarPro로 다시 읽어 확인했고, Guitar Pro·TuxGuitar로 열어 보지는 못했습니다.
- STEP 4: 발음은 가사 텍스트에서 규칙으로 추정한 값입니다. 한국어 실제 가사 두 곡(888음절)을 공개 변환기 g2pk2와 비교해 92.0% 일치했고,
  다른 곳은 대부분 띄어쓰기 경계 연음(표준 발음법 제15항)을 적용하느냐의 차이입니다. 정답 발음이 있는 자료로 잰 정확도는 없습니다.
  멜리스마는 악보가 있는 두 곡에서 악보 음표를 쓰면 정답 9개 중 7개를 맞히고 오검출 0, 앱 자동 음표를 쓰면 3개(멜리스마 음표 누락 때문).
  Windows 실행은 확인하지 못했습니다. 자세한 내용은 STEP_4_IMPLEMENTATION_REPORT.md.

## 문제 해결

**NVIDIA GPU가 있는데 분리가 느리다 / "GPU를 쓸 수 없어 CPU로 분리했습니다" 경고** — 설치된 PyTorch가 CPU판입니다.
`install_separation.bat`을 다시 실행하세요. CPU판을 지우고 드라이버에 맞는 GPU판을 설치한 뒤, GPU를 인식하는지 마지막에 알려 줍니다.
"드라이버가 오래되어"라는 안내가 나오면 NVIDIA 드라이버를 먼저 업데이트하세요. 설치 뒤 분석 설정의 [GPU 확인]이 GPU 이름을 보여 주면 됩니다.
"nvidia-smi는 있지만 CUDA 버전을 읽지 못했습니다"가 나오면 그 아래 줄에 nvidia-smi가 보여 준 내용이 있습니다. 드라이버와 통신하지 못한다는
문구면 드라이버를 다시 설치하세요. 명령 프롬프트에서 `nvidia-smi`를 실행해 오른쪽 위 `CUDA Version`이 보이면 그 버전에 맞춰 직접 고를 수 있습니다.

```bash
install_separation.bat --build cu126
```

(`cu126`은 CUDA 12.6 이상, `cu130`은 13.0 이상, `cu132`는 13.2 이상인 드라이버에서 씁니다.)

**`보컬 분리에는 PyTorch와 Demucs가 필요합니다`** — `install_separation.bat`을 실행하세요.
반주 없는 음원이라면 분석 설정의 보컬 분리를 '분리 안 함'으로 바꿔도 됩니다.

**`Demucs 모델(htdemucs)을 불러오지 못했습니다`** — 처음 분석할 때 모델을 내려받습니다. 인터넷 연결을 확인하세요.
모델은 사용자 폴더의 `.cache` 아래(Hugging Face 또는 torch hub 캐시)에 저장됩니다.

**`ModuleNotFoundError: No module named 'PySide6'`, `No module named pip` (C:\msys64\...)** — 공식 Python이 아니거나
가상 환경을 켜지 않은 상태입니다. `run.bat`을 쓰면 공식 Python을 찾아 처리합니다. `python -m amp`도 원인과 해결 방법을 안내합니다.

**`python`을 입력하면 Microsoft Store가 열린다** — 설치 때 PATH 추가를 하지 않은 경우입니다. `py`를 쓰세요.

로그는 `%LOCALAPPDATA%\SONATLAS\SONATLAS\logs\`에, 자동 저장본은 같은 위치의 `recovery\`에 있습니다.
프로그램 안에서는 상태 표시줄의 **로그** 버튼으로 펼쳐 볼 수 있습니다.
