## 4. Phase 1에서 할 일

명세 21장 Phase 1(기반 및 안정화) 항목에 맞춘다.

1. **입력별 악기 결과 구분 (15.1, 14.3)**: 악기 파일 자리를 (악기, 입력 종류, 만든 모델)로 나눈다. 기존 파일은 옮기거나 지우지 않고,
   목록의 `input`·`made_by`로 읽는다. 반주 입력 결과에는 반주 파일의 해시와 분리 결과 키를 적는다.
2. **모델 등록 정보 (13.2)**: 설치 여부, 파일 위치, 버전, 크기, 체크포인트 해시, 실행 장치, 의존성, 라이선스, 지원 기능, 상태.
   프로그램 전체 정보로 두고 프로젝트에는 쓰지 않는다. GUI 프로세스에서 torch를 불러오지 않는다. 사용자의 `MelBandRoformer.ckpt`는 경로만 읽는다.
3. **공통 결과 메타데이터·상태 (17.1, 17.2)**: 새 분석 결과 파일이 함께 쓰는 머리말과 상태 값, 소스가 바뀌면 지우지 않고 stale로 표시.
4. **분석 프로필 (13.4)**: Lite·Standard·Advanced. 설치된 모듈과 장치에 따라 실제로 켤 수 있는 기능을 정한다. Lite는 그대로 둔다.
5. **오류 격리 (13.3)**: 기능별 사용 가능 여부와 이유(미설치, CUDA 없음, 체크포인트 오류 등). 한 모듈이 실패해도 앱은 계속 동작.
6. **Windows 검증 준비**: 사용자가 Windows에서 실행할 점검 스크립트(GPU·모델 등록 정보·짧은 분석 시간)와 결과 파일. 이 컨테이너에서는 Windows를 실행할 수 없다.

## 5. 피치 모델 후보 (명세 4.2)

PyPI 휠을 내려받아 메타데이터와 파일을 확인했다. 가중치 파일을 따로 내려받지 않았다.

| 후보 | 라이선스 (휠 메타데이터) | 휠 크기 | 가중치 | 의존성 | 확인한 것 |
|---|---|---|---|---|---|
| torchcrepe 0.0.24 | MIT | 72MB | 휠 안 `assets/full.pth` 89MB, `tiny.pth` 2MB | torch, torchaudio, resampy, librosa, tqdm | 신경망 구조가 단순하다(합성곱 6층 + 분류 360칸, 20cent 간격). 같은 구조를 torch만으로 다시 만들어 휠의 가중치를 읽었다. 10초 220Hz 합성음: 최댓값 칸 220.8Hz. CPU 4스레드(전체 시험을 함께 돌리는 중)에서 full 18.0초(0.56배속), tiny 1.7초(6배속) |
| torchfcpe 0.0.4 | MIT | 40MB | 휠 안 `fcpe_c_v001.pt` 43MB | torch, torchaudio(Resample), einops, local-attention(→ hyper-connections) | 실행하지 않음. 구조가 conformer + local attention이라 다시 만들기가 더 크다 |
| RMVPE | 확인하지 않음 | — | Hugging Face 저장소에서만 배포 | — | 명세("외부 모델 파일을 임의로 내려받지 않는다")에 따라 내려받지 않음 |

- **torchaudio**: PyTorch CPU 저장소의 최신판이 2.11.1(`torch>=2.11`)이고 개발 환경 torch는 2.15다. torch 2.15와 함께 쓸 수 있는지는 확인하지 않았다.
  torchcrepe는 파일 읽기(`load.py`)에만 torchaudio를 쓰지만 패키지 `__init__`에서 바로 불러오므로, 패키지를 그대로 import하면 torchaudio가 필요하다.
- RoFormer·MMS처럼 신경망을 torch만으로 옮기면 torchaudio·resampy 없이 가중치만 쓸 수 있다 (가중치는 `pip install --no-deps torchcrepe`로 설치된 파일을 경로로 읽음).
- CPU 속도는 부하가 있는 상태에서 잰 값이다. GPU(RTX 3070 Ti) 속도는 재지 않았다.
